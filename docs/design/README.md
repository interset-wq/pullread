# UI 设计交付目录（docs/design/）

设计师（agent）的专属交付区：**只产出设计规范与设计板，不写实现代码**。
实现由开发侧依据本目录的规范落地；实现改动设计时，设计师同步更新对应文档。

## 目录结构

```
docs/design/
├── README.md            # 本说明：职责边界与交付约定
└── home-redesign/       # 每个改版主题一个子目录
    ├── home-redesign.md # 设计规范（结构 / token / 交互规则 / 验收清单）
    ├── boards.png       # 方向探索：三方向同屏对比
    ├── iter4.png        # 过程定稿：仓库/本地切换式双态
    └── iter9.png        # 最终定稿：手机 + 平板 + 少内容态
```

## 交付约定

1. **主题子目录**：每个 UI 改版主题一个子目录（`<topic>.md` 规范 + 设计板）。
2. **HTML 与 PNG 同时入库**（2026-11 起）：HTML 设计稿是正式交付物（无视觉
   能力的 agent 依赖 HTML 读取设计），chrome 无损渲染出的 PNG 随附；过程稿留在
   `temp/` 不入库，只收定稿与关键里程碑。
3. **手机 / 平板分文件**（2026-11 起）：每个主题至少提供 `phone.html/.png` 与
   `tablet.html/.png` 两套，不得混在同一文件里；平板帧缺失时先补板再定稿。
4. **规范即契约**：结构、token、交互规则、验收清单写在规范文档里，实现方照此
   落地；token 变更必须先改规范。
5. **设计稿仅供参考**（2026-11 起）：设计板/HTML 是方向参考，不是逐像素契约；
   实现时发现设计稿不合理（实现代价过高、与已有 UI 冲突、体验更差）应**及时汇报**，
   由用户决定取舍，不得默默偏离或默默照做。
6. **UI 一致性基准以 home 为准**（2026-11 起）：跨主题的页面底色、顶栏（header）
   底色与高度、卡片/描边/分隔等基础面统一沿用 home-redesign.md 的 token；
   各主题文档不得另立近似色值。
   - 屏幕 bg：浅色 `#FFFFFF`（纯白），深色 `#141512`
   - Header：与屏底同色（`#FFFFFF` / `#141512`），高度默认 56dp
     （kToolbarHeight），无阴影无 tint；标题/左上标识区对齐 home（34px logo，左对齐）
   - 卡片 `#FFFFFF` / `#1D1F1B`；描边 `#E5E2D8` / `#34362F`；分隔 `#F2F0E8` / `#2A2C26`
7. **品牌约束**：纯白底 `#FFFFFF`（2026-11 起，原纸白 `#FBFAF6` 已弃用）× 松绿
   `#1F6F54`；深浅色成对给值。
8. 设计师可随时新增主题子目录；跨主题的通用 token 沉淀在本文件的「UI 一致性基准」，
   待体量增大再抽 `docs/design/tokens.md`。
