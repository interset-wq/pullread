# UI 设计交付目录（docs/design/）

设计师（agent）的专属交付区：**只产出设计规范与设计板，不写实现代码**。
实现由开发侧依据本目录的规范落地；实现改动设计时，设计师同步更新对应文档。

## 目录结构

```
docs/design/
├── README.md            # 本说明：职责边界与交付约定
└── home-redesign/       # 每个改版主题一个子目录
    ├── home-redesign.md # 设计规范（结构 / token / 交互规则 / 验收清单）
    ├── boards.png       # 方向探索：三方向同屏对比
    ├── iter4.png        # 过程定稿：仓库/本地切换式双态
    └── iter9.png        # 最终定稿：手机 + 平板 + 少内容态
```

## 交付约定

1. **主题子目录**：每个 UI 改版主题一个子目录（`<topic>.md` 规范 + 设计板 PNG）。
2. **设计板来源**：HTML 设计稿由 chrome 无损渲染为 PNG 后入库；过程稿留在
   `temp/` 不入库，只收定稿与关键里程碑。
3. **规范即契约**：结构、token、交互规则、验收清单写在规范文档里，实现方照此
   落地；token 变更必须先改规范。
4. **品牌约束**：纸白 `#FBFAF6` × 松绿 `#1F6F54`；深浅色成对给值。
5. 设计师可随时新增主题子目录；跨主题的通用 token 沉淀在各自规范里，待多主题
   稳定后抽 `docs/design/tokens.md`。
