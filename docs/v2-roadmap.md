# PullRead v2 总体路线

> 状态：草案 v0.1（2026-11-14）
> 基线：`v1.14.0-rc2`（v1 功能面已基本完成）
> 主轴：**继续优化阅读体验**
> 本文是 v2 的范围与阶段契约；单个特性的详细设计在每期开工前补
> `docs/ui/<topic>.md`，不直接写进本文。

## 1. 为什么是 v2

v1 已经把「克隆 → 阅读 → 拉取 → 再阅读」的主链路做完整：仓库/本地文件夹、
Markdown/Notebook/代码渲染、TOC、查找、标签、书签、更新收件箱、纸感主题、
跨平台构建都已具备。继续横向堆功能的收益在下降。

v2 只做一件事：**让长文档的阅读方式更接近书，让多篇笔记的对照阅读成为可能。**
判断一个新需求是否属于 v2：它是否直接改善"连续读"或"对照读"；否则进入 backlog，
不进 v2。

## 2. 目标与非目标

### 2.1 v2 目标

1. **电子书模式**：把一个文档型仓库（`docs/` 下多个目录、每个目录一个 README）
   组织成一本有章节顺序的书，按书的体验连续阅读。
2. **多开阅读**：平板/桌面左右分屏、手机快速切换，跨仓库与本地文件夹对照阅读。
3. **阅读内核收口**：单篇、电子书、分屏共用同一个阅读面板，渲染/查找/进度只有
   一份实现，避免 v2 引入两套阅读器。

### 2.2 非目标（沿用 v1 边界）

- 不做私有仓库鉴权、协作、评论、双链/图谱、TTS、PDF、阅读统计、静态站点生成、
  平台 REST API 依赖。
- 不做跨设备同步；多开状态只在当前会话内有效。
- v2 不把仓库变成可编辑项目：仓库文件仍然只读，写回只属于本地文件夹。
- 不做全书一次性渲染（违反长文档懒布局不变量），不做左右翻页动画。

## 3. 两个支柱

### 3.1 电子书模式

**问题**：文档型仓库的真实结构是"目录 = 章"，但当前只能按目录树逐级打开，
缺少章节顺序、书级目录和连续阅读的衔接。

**已定行为**

| 决策点 | 结论 |
| --- | --- |
| 章节来源 | 混合：显式大纲优先，缺失时自动推断 |
| 大纲优先级 | `.pullread-book.json` → `SUMMARY.md` → `_sidebar.md` → 目录结构自动推断 |
| 自动推断 | 选定根下，每个含 `README.md` 的子目录为一章；同目录其余 Markdown 按自然排序聚合 |
| 书根范围 | 自动探测（含大纲标记的目录优先，否则 `docs/`，再退仓根），进入后可切换根目录 |
| 阅读形态 | 章内连续滚动，章末衔接下一章；不在一个滚动流里渲染全书 |
| 章节导航 | 书级目录（宽屏侧栏/窄屏弹层）+ 上一章/下一章 + 章内 TOC |
| 进度 | 章内比例沿用 `RepoMeta` 现有按文件进度；书级只额外记录"上次读到哪一章"，不复制章内比例 |
| 本地来源 | 本地镜像与 Git 仓库走同一套书单逻辑，来源根统一处理 |

**不做**：EPUB/PDF 导出、整书离线打包、章节内容改写、自动翻译。

### 3.2 多开阅读

**问题**：对照两篇笔记时需要反复返回再进入，阅读位置和查找状态都会丢失。

**已定行为**

| 决策点 | 结论 |
| --- | --- |
| 形态 | 平板/桌面左右分屏；手机保留单阅读页 + 底部快速切换器 |
| 栏数 | 最多两栏，不做三栏/拖拽重排 |
| 来源 | 跨仓库、本地文件夹、代码页可任意组合 |
| 状态 | 仅当前会话有效；退出阅读页即清空分屏，不跨重启恢复 |
| 进度 | 两栏各自独立写 `RepoMeta` 进度，互不覆盖 |
| 分屏阈值 | ≥900dp 默认分屏；600–900dp 提供手动「分屏」开关；<600dp 用切换器 |
| 打开规则 | 已有一篇时，第二篇进入非活动栏；手机端两篇都保留，用底部胶囊切换 |

**不做**：浏览器式无限标签页、跨重启会话恢复、同一文件镜像滚动。

## 4. 共同底座：阅读内核抽取

电子书和多开都必须复用现有阅读器，否则表格/公式/Mermaid/长文懒布局会出现
第二套实现。v2 的第一阶段是先做无感重构：

```text
lib/src/books/                 新增：书单与书根
├── book.dart                  BookOutline / BookChapter / BookRoot 模型
└── book_outline.dart          三种显式大纲、自动推断、书根探测
                               （书级进度落在 RepoMeta.bookProgress，暂不单文件）

lib/src/ui/reader/             新增：阅读内核
├── reader_controller.dart     从 _MarkdownViewerPageState 抽出的加载/查找/进度状态（待拆）
├── reader_pane.dart           正文 + TOC + 查找 + 进度条（过渡期仍含 Scaffold/AppBar）
├── book_reader_page.dart      电子书入口：书单、书根切换、继续阅读
└── split_reader_page.dart     分屏薄壳 + 会话状态（M3）

markdown_viewer.dart           公开 API 不变，内部转为 ReaderPane 薄壳
```

约束：

- `ReaderPane` 最终不持有 `Scaffold`/`AppBar`；页面壳负责标题栏、菜单、返回。
  过渡期单篇/电子书都走完整页面，M3 前拆出无 chrome 形态。
- 懒布局、`AutoScrollTag`、标题槽位、用户滚动才写进度、`protectTableMathPipes()`
  等不变量原样保留，只换承载位置。
- `MarkdownViewerPage` 的构造参数与调用方保持兼容，先重构后加功能。
- 章节界面的 TOC 跳转、文内查找、书签、导出长图必须复用同一套 controller 行为。

## 5. 里程碑

里程碑不承诺日期，按出口条件推进。每个里程碑单独 PR，合并前更新
`PLAN.md` 的进行中表与对应文档。

### M0 阅读内核抽取（无用户可见变化）

- 抽出 `ReaderController` / `ReaderPane`，改造 `MarkdownViewerPage`。
- 补回归测试：续读进度只在用户滚动后落盘、文内查找定位、TOC 跳转、表格/公式/
  Mermaid 渲染、长文懒加载、导出长图。
- 出口：`flutter analyze --fatal-infos` + `flutter test` 通过；真机阅读回归无差异。

### M1 书单与书根（数据层）

- 实现三种显式大纲解析与自动推断、书根探测、章节模型。
- 书单结果按来源缓存到 `.meta/`，文件删除/改名/分支切换后失效重算。
- 补单元测试：真实大纲样例、空/坏大纲、重复章节、相对路径、`../`、编码。
- 出口：对文档型仓库能稳定产出章节列表；解析失败自动回退，不阻塞阅读。

### M2 电子书阅读（MVP）

- 仓库页/首页入口「以电子书打开」，书级目录、章内阅读、上一章/下一章。
- 书级进度与续读、书签复用、章节切换后保持阅读位置。
- 宽屏书级 TOC 侧栏；窄屏弹层；书根切换。
- 出口：一本 30+ 章的文档仓库可从头连续读到尾；退出重进恢复章与章内位置。

**当前状态**：MVP 已落地——仓库页 AppBar「电子书」入口、书单/书根切换、
书级进度（`RepoMeta.bookProgress`）、章节上下篇与书名标签、宽屏 280dp
书目录侧栏、窄屏底部书目录弹层。待 30+ 章真机连续阅读验收。

### M3 多开阅读

- `ReaderSession` 与双栏壳；平板/桌面分屏、手机底部切换器。
- 跨来源组合、两栏独立查找/进度/菜单、分屏开关与窗口尺寸变化处理。
- 出口：两篇不同来源的文档可同时阅读并各自保存进度；旋转/缩放不串状态。

### M4 联调与收尾

- 电子书 + 多开组合（左右两栏各自可处于书内章节）。
- 设置项（书根默认、分屏偏好）、空状态、错误提示、文档与截图。
- 出口：v2.0.0-rc1 发布，完成 Android 真机与 Windows 桌面验收。

## 6. 验收基线

**单篇阅读不回归**（M0 起每个里程碑都必须满足）

- 续读恢复位置正确，程序化滚动不写坏进度。
- 文内查找计数与跳转位置正确，章节内精确定位不退化。
- TOC 筛选/编号、书签、收藏、最近阅读、导出长图、图片保存均正常。
- 表格横向/换行双档、公式、Mermaid、代码折叠、Notebook 渲染不变。
- 大仓库打开仍走索引缓存，不在 UI isolate 递归扫描。

**电子书**

- 大纲仓库（mdBook/GitBook/docsify）章节顺序与显式大纲一致。
- 无大纲仓库按目录推断，章节不重复、不丢文件、排序稳定。
- 书级进度与单篇进度一致：从书里读一章，再从目录树打开同一文件，位置相同。
- 切换书根/分支后书单刷新，旧进度不误用到同名新文件。

**多开**

- 两栏独立滚动、独立查找、独立菜单，互不串状态。
- 两栏进度分别落盘，退出重进各自可恢复。
- 手机切换器切换后不重建页面、不丢失滚动位置。
- 窗口从窄到宽/从宽到窄时，分屏状态安全降级。

## 7. 风险与约束

| 风险 | 处理 |
| --- | --- |
| `markdown_viewer.dart` 近 4k 行，抽取范围失控 | M0 只搬状态与正文，不改渲染逻辑；按 controller/pane 两步提交 |
| 电子书被做成"第二个阅读器" | 强制复用 `ReaderPane`；新增渲染相关代码必须进共享层 |
| 全书连续滚动的诱惑 | 明确不做；章间只做衔接，不合并滚动流 |
| 大纲格式差异 | 解析器分层 + 单测样例；任何解析失败回退自动推断 |
| 书级进度与单篇进度双写冲突 | 单篇进度仍是唯一权威；书级只记录"上次在哪一章"，章内比例从单篇进度派生 |
| 分屏内存压力 | 最多两栏；离开页面释放；不在后台保留会话 |
| 会话状态误持久化 | 多开状态只存内存；不写 `SharedPreferences` 或 `.meta` |

## 8. 文档治理

v1 遗留的一次性计划与审计文档在 v2 启动时清理，常青文档保留并继续维护。

| 文件 | 现状 | v2 处置 |
| --- | --- | --- |
| `PLAN.md` | 停在 v1.12.0，已过时 | 重写为 v2 执行板，指向本文 |
| `README.md` 路线图 | 混合 v1 已完成项与零散待办 | 改为 v2 两条主线 + 收尾项 |
| `docs/settings-redesign.md` | 设置页改版已全部落地 | 删除；结论已在代码与 `docs/ui/settings-redesign/` |
| `docs/user-feedback.md` | 2026-11-07 静态审计快照，多数已修复 | 删除；删除前把仍未落地且有价值的条目迁入 `PLAN.md` backlog |
| `docs/ui/**` | 已实施的 UI 规范与 HTML 设计稿 | 保留为设计基线；PNG 已删除，`docs/ui/README.md` 标注"已实现" |
| `docs/ios-test-plan.md` | v1 真机验收清单尚未全部通过 | 保留为 v1 收尾项，不阻塞 v2 |
| `docs/git-sync.md`、`rendering.md`、`reading.md`、`local-folders.md`、`platform.md`、`perf.md` | 常青技术文档 | 保留；改到对应区域时同步更新 |
| `AGENT_OPS_LOG.md` | 跨 agent 操作日志 | 保留，继续追加 |

清理原则：

- 删除前先确认其中的未完成项已经迁入 `PLAN.md` 或明确放弃。
- 不保留"已完成计划书"作为历史包袱；需要追溯时用 git 历史。
- 设计规范（`docs/ui/`）与一次性计划（建议书、审计快照）区分对待：前者是
  实现依据，后者用完即删。

## 9. 版本与发布

- v2 开发期使用 `2.0.0-rc*` 预发布 tag，稳定版 `2.0.0` 在 M4 验收后发布。
- 每个里程碑合并即更新 `PLAN.md` 状态；发布仍走 `v*` tag + GitHub Actions，
  不手动上传 APK。
- v1 的真机验收缺口（行选区、SAF 写回、图标切换、音量键、iOS/iPadOS）继续按
  `PLAN.md` 收尾清单执行，不与 v2 功能开发混在同一 PR。
