# 设置页重设计建议书

> 2026-11-06 建议稿，尚未实现。范围是 `lib/src/ui/settings_page.dart` 及其入口，
> 不改变任何 `SharedPreferences` key 与既有功能语义。目标是先解决「一页太长、
> 分组混乱、危险操作与普通设置混排」，再补交互细节。

## 1. 现状审计

### 1.1 结构

当前是一个 `ListView`（`settings_page.dart:40`），把 6 个一级标题和 24 个可交互项
平铺在同一页：

| 分组 | 项目 |
|---|---|
| 克隆 | 默认平台、默认用户名、自动拉取同步、目录树模式 |
| 代码字体 | JetBrains Mono / Consolas |
| 阅读 | 屏幕常亮、手势翻页、表格不换行、折叠块默认展开、正文行距、页边距、代码行号、长代码块折叠、代码折叠阈值、历史长度 |
| 应用图标 | 5 个图标选项 |
| 数据 | 清空阅读历史、清空收藏、未写回的修改、存储占用、隐藏默认忽略项、自定义隐藏规则 |
| 应用 | 检查更新、应用信息 |

按常见行高估算，整页约 2000–2300 dp，360×800 的屏幕需要滚动约 3 屏。设置项本身
没有搜索、没有「当前值」总览、没有恢复默认入口。

### 1.2 具体问题

1. **分类维度混用**：代码字体单独成节，但代码行号、代码折叠却在「阅读」里；
   目录树模式属于浏览方式，却放在「克隆」里；主题在首页菜单，阅读字号在阅读页，
   设置页反而找不到。
2. **长说明撑高行高**：自动拉取、目录树、表格不换行的说明有 2–3 行
   （`settings_page.dart:96`、`109`、`173`），是页面变长的主要来源之一。
3. **危险操作与普通操作混排**：清空历史/收藏与存储占用、未写回修改、隐藏规则
   同组（`settings_page.dart:322-392`），缺少视觉隔离。
4. **滑杆挤压文字**：每个滑杆固定 140 dp 放在 `trailing`
   （`settings_page.dart:198`、`218`、`260`、`281`），小屏下标题和副标题空间不足。
5. **写盘过于频繁**：滑杆 `onChanged` 每跳一次就调用 `setLineHeight` 等
   （`settings_page.dart:206`、`226`、`268`、`289`），对应 setter 每次都会
   `SharedPreferences` 写盘（`app_prefs.dart:355-367`）；默认用户名也是逐字写盘
   （`settings_page.dart:86`、`app_prefs.dart:300-306`）。
6. **平台差异误导**：应用图标只在 Android 生效，但所有平台都显示整组选项
   （`settings_page.dart:296-320`）；Windows/iOS 上点击只会静默存偏好。
7. **「检查更新」歧义**：设置页指应用 Release，仓库页指 git 远端更新，两个入口
   同名但语义完全不同（`settings_page.dart:398`、`repo_page.dart:496`）。
8. **缺少收尾能力**：没有搜索、没有恢复默认、清空操作前看不到数量，
   搜索历史只能逐条删除，没有「清空搜索历史」。

## 2. 设计原则

1. **两级结构**：设置首页不超过 6 行，任何原有设置最多 2 次点击可达。
2. **按任务分组**：按「我在读 / 我在找仓库 / 我在清理数据」分，而不是按数据类型。
3. **一页一件事**：每个子页只放 2–4 个小组，组内用一张卡片包住。
4. **一句话说明**：副标题只留一行；长解释收进右侧 `?` 帮助弹层，不占列表高度。
5. **危险操作靠后**：数据页底部单独「危险操作」组，红色图标/文字 + 二次确认。
6. **平台诚实**：不生效的设置直接不显示，而不是显示后静默失败。
7. **渐进披露**：高级项（折叠阈值）放在子页，依赖项在开关关闭时禁用。
8. **不换视觉语言**：继续用 Material 3 + teal seed，不引入新品牌色，不改 `AppPrefs`。

## 3. 推荐信息架构

### 3.1 设置首页

```text
设置
├─ 阅读与显示      字号、行距、边距、阅读行为、代码块
├─ 外观与图标      主题、桌面图标
├─ 仓库与同步      默认平台、用户名、自动同步、目录树
├─ 文件显示        隐藏项、自定义忽略规则
├─ 存储与数据      占用、待写回、历史、收藏
└─ 关于 PullRead   v1.12.0 · 许可证 · 项目主页
```

首页只保留导航行，不放开关和滑杆；每行右侧显示当前值（如「跟随系统」「1.75」
「3 条规则」），左侧用 40 dp 的 tonal 圆形图标。

### 3.2 阅读与显示

页内再分 4 张卡片：

- **排版**：正文行距、页边距；可选增加「阅读字号」（见 6.3）。
- **阅读行为**：屏幕常亮、手势翻页、表格不换行、折叠块默认展开。
- **代码块**：代码字体、代码行号、长代码块折叠、折叠阈值。
- **首页**：最近阅读条数。

每项一句话：例如表格不换行 →「超宽表格横向滚动」；自动拉取 →「启动时后台更新
所有仓库」；目录树 →「目录就地展开，不进入下一级」。

### 3.3 外观与图标

- **主题**：跟随系统 / 浅色 / 深色，三选一，保留图标。
- **桌面图标**：5 个选项改为网格（手机 3 列、平板 5 列），选中态加勾选角标；
  仅 Android 显示，下方一行说明「部分机型需重启桌面」。
- 首页「更多 → 主题」保留为快捷入口，但设置页是正式入口；两处共用同一个选择组件。

### 3.4 仓库与同步

- **默认平台**：把横向滚动的 `SegmentedButton` 改成 4 行单选列表，每行显示域名
  （GitHub / Gitee / GitCode / GitLab）。当前实现在小屏上会隐藏右侧选项。
- **默认用户名**：输入框，失焦/提交时保存；帮助文案缩成一行
  「留空则只能粘贴完整 URL」。
- **自动拉取同步**：开关。
- **目录树模式**：开关，从「克隆」移到「仓库与同步」。

### 3.5 文件显示

- **隐藏默认忽略项**：开关。
- **自定义隐藏规则**：导航行，副标题显示条数；编辑仍用现有弹窗/页面。
- 可选「恢复默认规则」，与全局恢复默认分开。

### 3.6 存储与数据

普通操作：

- 存储占用（导航）
- 未写回的修改（导航，异步数量；有冲突时红色角标）
- 清空搜索历史（新增，若实现）

底部「危险操作」：

- 清空阅读历史
- 清空收藏

两项使用 error 色，点击后二次确认；能拿到数量时在副标题显示
「最近阅读 12 条 / 收藏 8 篇」，让用户知道代价。

### 3.7 关于

保留现有关于页（`settings_page.dart:520-650`），首页「关于 PullRead」行显示版本号。
「检查更新」只保留在关于页，并改名为「获取最新版本」，避免与仓库页的
「检查远端更新」混淆。包名、许可证、项目主页维持原样。

## 4. 视觉与组件规范

### 4.1 分组卡片

- 分组标题放在卡片外，`labelLarge` + `onSurfaceVariant`，左对齐。
- 卡片：`Card` + `surfaceContainerLow`，圆角 12 dp，`elevation: 0`；
  组内用 `Divider(height: 1, indent: 56)` 分隔。
- 页面左右 padding 16 dp；组间距 24 dp；卡片底部 32 dp。

### 4.2 行样式

- **导航行**（`SettingsNavTile`）：leading 40 dp tonal icon，title，单行 subtitle，
  trailing 为当前值 + `chevron_right`。
- **开关行**：`SwitchListTile`，不要 chevron；subtitle 最多一行。
- **滑杆行**（`SettingsSliderTile`）：标题和数值同一行（数值用 `labelLarge` 的
  小胶囊），滑杆独占下一行，宽度撑满卡片内容区；拖动时实时更新数值标签，
  `onChangeEnd` 才写偏好。
- **危险行**：icon 与 title 用 `colorScheme.error`，仍保留二次确认。

### 4.3 应用图标网格

- 预览 64 dp，圆角 16 dp；选中项 2 dp primary 描边 + 右上角 check 角标。
- 标签 `bodySmall`，最多一行；手机 3 列，避免 5 个标签在 360 dp 宽度下挤成两行。
- 非 Android 直接隐藏整组，不显示禁用态。

### 4.4 响应式与无障碍

- 内容区最大宽度 720 dp，居中；Windows/平板不把滑杆拉满整块屏幕。
- 触控目标不小于 48 dp；滑杆加 `Semantics` 标签和当前值。
- 文本放大到 2.0 不溢出；320 dp 宽度下不出现横向滚动。
- 不只靠颜色表达选中/错误状态，配合勾选、图标或文字。

## 5. 交互细节

1. **当前值可见**：主题（跟随系统）、行距（1.75）、页边距（16 dp）、
   折叠阈值（30 行）、最近阅读（5 条）、忽略规则（3 条）。
2. **滑杆只在结束时写盘**：页面内用本地 draft 值保证拖动预览，
   `onChangeEnd` 调 `prefs.setXxx`；避免每帧 `SharedPreferences` 写入。
3. **用户名改为失焦/提交保存**：不要每个字符触发 `setDefaultOwner`。
4. **依赖项禁用**：长代码块折叠关闭时，折叠阈值行降为 50% 透明度并禁用，
   副标题提示「先开启长代码块折叠」。
5. **恢复本页默认**：子页 AppBar 右侧溢出菜单提供；只重置本页偏好，
   不删除仓库、历史、收藏；完成后 SnackBar 提示。
6. **删除确认**：标题 + 后果 + 数量；确认按钮用 error 色，取消为普通 TextButton。
7. **待写回角标**：首页「存储与数据」行显示数量角标；数据页内仍保留明细。
8. **搜索（第二阶段）**：设置首页 AppBar 放搜索图标，按设置名和别名检索
   （字号/字体/夜间/行距/边距/缓存/忽略/历史…），结果带面包屑，点击进入
   对应子页并滚到该项。第一阶段不做，避免为了搜索先建一套目录元数据。

## 6. 实施计划

### 6.1 第一阶段：信息架构（约 0.5–1 天）

1. 新增 `lib/src/ui/settings/`，把根页与子页拆开：
   - `settings_page.dart`（根）
   - `reading_settings_page.dart`
   - `appearance_settings_page.dart`
   - `repo_settings_page.dart`
   - `file_display_settings_page.dart`
   - `data_settings_page.dart`
   - `about_page.dart`（把私有 `_AboutPage` 公开并移出）
   - `settings_components.dart`（分组卡片、导航行、滑杆行）
2. 保持 `SettingsPage(prefs: prefs)` 构造签名，首页入口不变；子页同样接收 `AppPrefs`。
3. 所有长说明压缩为一行；完整解释放进 `showModalBottomSheet` 帮助层。
4. 应用图标组按 `Platform.isAndroid` 显示。
5. 更新路径文案：`home_page.dart:220` 的「设置 → 未写回的修改」改为
   「设置 → 存储与数据 → 未写回的修改」，并同步 README/AGENTS.md 中的路径。
6. 不做偏好迁移、不改 key、不改功能逻辑。

### 6.2 第二阶段：交互修正（约 0.5 天）

1. 滑杆/用户名输入改为本地 draft + 提交时写盘。
2. 折叠阈值依赖禁用。
3. 子页「恢复本页默认」。
4. 待写回数量角标；能低成本拿到的清空数量显示在副标题。
5. 应用更新入口改名「获取最新版本」。

### 6.3 第三阶段：可选增强（约 1–1.5 天）

1. 设置搜索与别名目录。
2. 阅读页排版改成「实时预览卡 + 全宽滑杆」，让用户不必回文章试效果。
3. 把阅读字号从 `SharedPreferences` 静态读写迁到 `AppPrefs`，设置页才可统一控制
   （当前字号只存在于阅读页菜单：`markdown_viewer.dart:72-73`、`2244-2260`）。
4. 平板/Windows 双栏（左导航 + 右内容）。

## 7. 验收标准

- [ ] 设置首页不超过 6 行，360×800 下无需滚动（或仅轻微滚动）。
- [ ] 任一原有设置最多 2 次点击可达。
- [ ] 导航行显示当前值；开关行副标题不超过一行。
- [ ] 清空历史/收藏集中在「危险操作」组，红色 + 二次确认。
- [ ] 非 Android 不显示桌面图标设置。
- [ ] 拖动滑杆只在结束时写盘；用户名不逐字写盘。
- [ ] 长代码块折叠关闭时，阈值控件禁用并有原因提示。
- [ ] 320 dp 宽度、2.0 文本缩放、深色模式下无溢出。
- [ ] `flutter analyze` 与 `flutter test` 通过；不修改任何偏好 key。
- [ ] 更新首页 SnackBar 路径文案、README、AGENTS.md 中的设置路径。

## 8. 风险与取舍

| 风险 | 处理 |
|---|---|
| 二级页面多一次点击 | 用当前值、清晰副标题抵消；主题保留首页快捷入口；后续加搜索 |
| 路径文案失效 | 全局搜索「设置 →」「设置页」「设置中」，一并更新 README/AGENTS |
| 重排导致功能回归 | 纯 UI 迁移，不改 `AppPrefs` 接口；补导航与开关的 widget 测试 |
| 视觉风格漂移 | 只用现有 M3/teal 色板；不新增自绘组件 |
| 关于页从私有类拆出 | 改成公开 `AboutPage`，保留包名/版本读取逻辑 |
| 恢复默认误伤 | 只重置当前子页偏好，不碰仓库、历史、收藏、搜索历史 |

不纳入本次范围：设置云同步、账号体系、按仓库覆盖设置、设置项权限控制。

## 9. 顺带发现的 UI 问题

1. **仓库页「更多」最后两项缺图标**（`repo_page.dart:494-498`），与上面三项不一致；
   建议补 `Icons.system_update_alt`、`Icons.link_off`。
2. **两个「检查更新」同名不同义**：设置页是应用 Release，仓库页是 git 远端。
   建议分别改为「获取最新版本」「检查远端更新」。
3. **搜索历史只能逐条删**（`app_prefs.dart:160`），数据页可加「清空搜索历史」，
   与清空历史/收藏并列。
4. **应用图标在 Windows 预览是空操作**：设置页应隐藏或明确标注「仅 Android」，
   避免用户以为切换失败。
5. **主题入口分散**：首页菜单、设置页（未来）各一处。保留两处没问题，
   但必须复用同一个选择组件，避免行为和文案分叉。

## 10. 给负责 agent 的建议顺序

1. 先只做第一阶段拆分与文案压缩，单独提交；这是收益最大、风险最低的一步。
2. 跑 `flutter analyze` + `flutter test`，再真机看 320 dp 和深色模式。
3. 第二个提交做滑杆/输入框写盘修正与依赖禁用。
4. 第三个提交再考虑恢复默认、角标、搜索；搜索不要和第一阶段绑在一起。
5. 每步同步更新 `AGENT_OPS_LOG.md`，路径变化同步 README/AGENTS.md。
