# 收件箱与收藏页改版设计规范（2026-11 定稿）

来源：真机截图审计（更新收件箱 math 45 项实测 + 书签弹层实测）+ 一轮迭代。
定稿板（HTML 入库）：`docs/ui/inbox-favorites/`——
手机 `phone.html`（收件箱常态 + 书签弹层）、平板 `tablet.html`
（横屏双栏 + 竖屏限宽）。过程稿在 `temp/inbox-favorites/`，不入库。
本文是 Flutter 实现的依据；改版动这里时同步更新。

## 1. 要修的问题（真机审计）

收件箱：
1. 分组头只有仓库名 + 数量，无同步时间感知
2. .gitignore 等配置变更与正文更新同等视觉权重，噪音大
3. 行操作只有「更新」chip，无已读/打开快捷动作
4. 无空态设计
收藏（书签弹层）：
5. 条目只有标题（小节名），不知道来自哪个文件/仓库
6. 进度与时间挤在一行小字，信息层级不清

## 2. 定稿设计

### 2.1 手机（< 600dp）

```
头部：返回 + 「更新收件箱」+ 全部已读（松绿文字钮）
分组头：仓库名（松绿 700）+ 同步时间（灰小字）+ 右侧数量胶囊（45 项）
更新行：
  图标章 38×38（md 灰 tint / 代码松橙，同目录树页 token）
  文件名 + 副行「目录 · 变更类型」（正文更新/配置变更）
  正文更新行右侧绿色「更新」chip
  配置变更行：无 chip、文件名等宽、副行标注（低相关，弱化）——视觉降噪
空态：居中灰字 + 图标章「收件箱空空如也」+ 引导「点『全部更新』检查各仓库」
书签（阅读页底部弹层）：
  标题行「书签 · n 条」+ 拖拽把手
  条目：书签图标章 + 小节标题（600 字重）+ 副行「文件名 · 位置 · 进度% · 时间」
  右侧删除钮；点击条目恢复阅读位置
```

### 2.2 平板

- **横屏（≥ 1000dp）**：收件箱列表 420dp 左栏（浅底 #FFFFFF 与屏底一致、
  靠 divider 区分，当前项
  绿 tint + 右缘指示条）+ 右栏**变更详情**：文件名（等宽）+ 元信息
  （目录 · 变更类型 · +n −n · 时间）+ diff 摘要卡（增行绿底/删行红底/
  上下文灰）+ 动作行（打开阅读·主钮 / 标记已读·副钮）
- **竖屏（600–1000dp）**：同手机结构，居中限宽 640dp。

## 3. 视觉 token（沿用既有设计板，新增）

| Token | 值 |
|---|---|
| 分组头 | 仓库名 14px 700 `#1F6F54`；同步时间 11.5px `#A5A296`；数量胶囊 11.5px 底 `#F1EFE7` |
| 变更 chip | 11.5px 600 松绿，底 `#E9F2ED`，圆角 999 |
| diff 摘要 | 卡描边 `#E5E2D8` 圆角 12；增行 `#EDF7F1`/`#14563F`，删行 `#FBEFEC`/`#7A3B2E`，上下文 `#FFFFFF` |
| 主按钮 | 松绿底白字圆角 11；副按钮白底描边 |
| 空态 | 图标章 52×52 圆角 18 绿 tint；文字 13.5px `#A5A296` |

## 4. 交互规则

1. 收件箱行点击：手机=直接打开文件阅读；平板横屏=右栏显示变更详情。
2. 「全部已读」一键清空全部分组（二次确认，防误触）。
3. 配置变更行不参与「更新」计数徽标（只统计正文更新）。
4. 书签条目点击恢复位置后关闭弹层；删除即时生效（无确认，可撤销时机
   由实现侧决定，弹层内不做复杂撤销流）。
5. 深浅色：diff 增删色、chip、空态章成对映射。

## 5. 实现落点（供开发侧）

- `lib/src/ui/`：收件箱页重构（分组头/行组件/空态）；平板 LayoutBuilder
  双栏 + diff 摘要组件（数据源：同步层的变更记录）
- 书签弹层：条目补来源文件与位置（bookmark 模型已有文件信息，补展示）
- 测试：分组头渲染、配置变更弱化逻辑、书签条目来源展示、空态
