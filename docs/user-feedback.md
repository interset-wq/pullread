## 1. 结论摘要

PullRead 的核心阅读链路已经比较完整：Markdown/代码/Notebook 渲染、目录树、TOC、文内查找、图片缓存、本地文件夹镜像与编辑、书签、标签、更新收件箱等能力都已具备。

但当前仍有一个**数据丢失级 P0**，以及若干会直接影响日常阅读的 P1：

1. 带尾斜杠的克隆地址可能把整个 repos 根目录当成目标目录递归删除。
2. 文内查找在长章节内无法真正跳到“下一处命中”。
3. 上一篇/下一篇会把图片、代码等非 Markdown 文件当 Markdown 打开。
4. 正文里的图片链接打开的是代码查看器。
5. 本地文件夹没有完整进入首页继续阅读、收藏、最近阅读和全局搜索。
6. 正文无法选中局部文字复制。
7. 代码/日志查看没有文件大小上限。
8. 本地 Markdown 编辑器遇到 GBK 文件会崩溃。
9. 数学公式会把 `$100 到 $200` 这类金额误判为公式。

建议顺序：先修 P0 并补回归测试，再修阅读主链路的 P1，最后做兼容性与体验增强。

## 2. P0：克隆尾斜杠可能删除所有仓库

### 2.1 问题

“添加仓库”允许输入完整 URL。当前仓库名直接取 URL 最后一段：

```dart
// lib/src/ui/home_page.dart
final name = url.split('/').last.replaceAll('.git', '');
```

如果用户从浏览器复制的地址带尾斜杠，例如：

```text
https://github.com/owner/notes/
```

则 `name` 为空。随后 `GitSyncService.clone()` 拼出的目标路径是：

```dart
// lib/src/git/sync_service.dart
final targetPath = '${parentDir.path}${Platform.pathSeparator}${repo.name}';
```

即 **repos 根目录本身**。`_prepareTarget(targetPath)` 发现该目录不是有效 git 仓库后，会执行递归删除：

```dart
// lib/src/git/sync_service.dart
dir.deleteSync(recursive: true);
```

### 2.2 影响

- 所有已克隆仓库被删除。
- `<reposRoot>/.meta` 下的阅读进度、收藏、书签、更新标记被删除。
- 目录索引缓存被删除。
- 之后才尝试克隆，且克隆目标变成 repos 根目录，仓库列表也无法正常恢复。
- 用户通常不会预期“多了一个斜杠”会造成本地数据清空。

同类异常名称也有风险：

- `https://host/owner/.`、`https://host/owner/..`
- `https://host/owner/.meta`
- 仓库名包含 `?query`、`#fragment` 或 Windows 非法字符
- 仓库名本身包含 `.git` 子串时，`replaceAll('.git', '')` 还会错误改名

### 2.3 建议修复

1. 用 `Uri.parse(url).pathSegments` 取最后一段，忽略空段，只移除末尾 `.git` 后缀。
2. 校验仓库名：
   - 非空；
   - 不是 `.`、`..`；
   - 不含 `/`、`\`、`:`、`?`、`*`、`"`、`<`、`>`、`|`；
   - 不以点开头（至少拒绝 `.meta`）。
3. 克隆前规范化目标路径，并确认目标父目录严格等于 repos 根目录，而不是只做字符串拼接。
4. `_prepareTarget()` 内部再加一层防御：不允许删除 repos 根目录、元数据目录或应用文档根目录。
5. 增加回归测试：
   - 尾斜杠 URL → 拒绝或正确归一化，绝不删除 repos 根；
   - `.`、`..`、`.meta` → 拒绝；
   - `my.git.repo` → 保留正确名称；
   - 目标路径越界 → 拒绝。

### 2.4 验收标准

- 输入尾斜杠 URL 时不会发生任何删除操作。
- 所有仓库名在进入 `GitSyncService.clone()` 前都是安全的单级目录名。
- 有单元测试覆盖上述输入。
- 测试不得在真实用户数据目录上执行删除路径。

## 3. P1：高频阅读链路问题

### 3.1 文内查找不能真正定位到同一章节内的下一处

**现象**

同一章节内有多个命中时，点击“下一处/上一处”只更新计数和底部预览，正文不会继续滚动。

**原因**

`lib/src/ui/markdown_viewer.dart` 的 `_jumpToMatch()` 只按命中行号找到所属标题，然后滚到标题顶部。同一标题下的多个命中最终都落到同一个标题位置。

**影响**

长文里用户看到“3/12”，但点下一处没有任何视觉变化，需要自己从章节开头继续找。

**建议**

- 为每个正文块记录源码行范围，命中后滚动到具体块，而不是只到标题。
- 或在同一章节内按命中偏移比例估算滚动位置，至少让下一处产生可见移动。
- 当前命中与普通命中使用不同底色，方便用户确认位置。
- 代码块内的命中也需要明确的“无法高亮但已定位”提示。

### 3.2 上一篇/下一篇会把图片、代码当 Markdown 打开

**现象**

同目录下同时存在 `.md` 与 `.png`、`.dart` 等文件时，阅读页底部的“上一篇/下一篇”或开启手势翻页后，会打开非 Markdown 文件并显示乱码。

**原因**

`_loadSiblings()` 收集同目录全部文件，没有过滤 `isMarkdown`；`_openSibling()` 固定构造 `MarkdownViewerPage`。

**建议**

- 只把 Markdown/ipynb 放进阅读页的“上一篇/下一篇”列表；或
- 复用 `openNoteFile()` 的分流逻辑，图片进图库、代码进代码查看器。
- 手势翻页和底部翻页条应使用同一套过滤规则。

### 3.3 正文图片链接打开代码查看器

**现象**

点击 `![图](images/a.png)` 或指向图片的 Markdown 链接，进入的是代码查看器，而不是图片查看器。

**原因**

`_openLocalFile()` 只判断 `note.isMarkdown`，其余全部进入 `CodeViewerPage`；`open_note.dart` 中已有的图片分流没有被复用。

**建议**

- 统一走 `openNoteFile()`，或在这里补 `note.isImage` 分支，进入 `ImageGalleryPage`。
- 对 PDF、压缩包等不支持的格式给出“暂不支持预览”的提示，而不是尝试按文本解码。

### 3.4 本地文件夹没有完整进入首页与全局搜索

**现象**

- 首页“继续阅读 / 最近阅读 / 收藏”只显示 git 仓库内容。
- 只有本地文件夹、没有任何 git 仓库时，首页搜索按钮被禁用。
- 全局搜索页只接收 git 仓库列表，不搜索本地镜像。

**原因**

- `_collectStarred(repos)`、`_collectRecents(repos)` 只接收 git 仓库目录。
- `RepoMeta.pushRecent()` 对本地镜像写入镜像目录自己的 `.meta`，首页不读取。
- 首页搜索按钮以 `repos.isEmpty` 作为禁用条件。
- `GlobalSearchPage(repos: repos)` 没有传入本地镜像。

**建议**

- 首页聚合收藏、最近阅读、继续阅读时同时遍历 `_repos` 与 `_localFolders` 的镜像目录。
- 本地镜像的最近阅读要么写入全局 `<reposRoot>/.meta/recents.json`，要么在读取时合并两套记录。
- 搜索按钮的可用条件改为 `repos.isNotEmpty || locals.isNotEmpty`。
- `GlobalSearchPage` 支持来源类型与显示名，避免本地文件夹与 git 仓库重名时混淆。
- “清空收藏/阅读历史”也要覆盖本地镜像，或在 UI 上明确只清理 git 仓库。

### 3.5 正文无法选中局部文字

**现象**

阅读页只能“复制全文”，不能长按选中一段、复制引用或查词。

**现状**

项目中未使用 `SelectionArea` / `SelectableText`；代码查看器支持行选区复制，但 Markdown 正文没有等价能力。

**建议**

- 用 `SelectionArea` 包住正文渲染区域，优先保证文字段落可选中。
- 处理与图片长按菜单、代码块横向滚动、链接点击之间的手势冲突。
- 如果短期无法支持富文本选区，至少提供“复制当前章节”作为过渡。

### 3.6 代码/日志查看没有大小上限

**现象**

打开大 `.log`、`.json` 或生成代码文件时可能长时间卡顿、内存飙升甚至 OOM。

**原因**

`lib/src/ui/code_viewer.dart` 的 `_load()` 直接 `readAsBytes()` 读取整文件，再整文件高亮并抽取大纲。

**建议**

- 设置硬上限，例如 5–10 MB；超过时只显示头部预览并提示“文件过大，已截断”。
- 或按需分页/分块加载，并关闭高亮或大纲。
- 错误提示中显示文件大小，避免用户误以为文件损坏。

### 3.7 本地 Markdown 编辑器遇到 GBK 会崩溃

**现象**

本地文件夹里的 GBK/GB2312 Markdown 可以正常阅读，但点击“编辑”后页面初始化异常。

**原因**

`lib/src/ui/markdown_editor.dart` 使用 `File(widget.filePath).readAsStringSync()`，默认按 UTF-8 严格解码，没有复用 `decodeTextBytes`。

**建议**

- 读取改为 `decodeTextBytes(await File(...).readAsBytes())`。
- 保存时明确编码策略：统一写 UTF-8，或保留原编码并提示用户。
- 增加 GBK 文件打开、编辑、保存的测试。

### 3.8 数学公式会把金额误判

**现象**

正文 `$100 到 $200` 会被当成行内公式，显示异常或被 KaTeX 解析成错误内容。

**原因**

`lib/src/notes/math_render.dart` 的正则为：

```dart
r'\$([^$\n]+?)\$'
```

它只要求两个 `$` 之间存在非空内容，不区分货币与公式。

**建议**

- 参考常见 Markdown 数学规则：开 `$` 后紧跟空白、闭 `$` 前是空白时不视为公式。
- 至少避免“数字开头 + 中文/空格 + 数字结尾”的金额模式。
- 提供转义说明或设置开关，让用户能关闭行内 `$...$` 解析。
- 增加 `$100 到 $200`、`$x$`、`$$...$$` 的回归用例。

### 3.9 正文搜索命中 front matter，但阅读页定位不到

**现象**

搜索标签、日期等 front matter 字段时能看到结果，打开文章后正文查找为 0 处，或无法跳转。

**原因**

`RepoSearchService` 搜索 Markdown 时直接使用原始文本，包含 front matter；阅读页的 `findTextMatches` 只针对 front matter 之后的正文。

**建议**

- 内容搜索前先 `FrontMatter.parse()`，只搜 `body`。
- 如果确实需要搜索 front matter，应在搜索结果中标注“front matter”，并让打开后的定位逻辑知道该命中不在正文中。

### 3.10 收藏/最近阅读会留下幽灵卡片

**现象**

文件被删除、仓库被重新克隆或文件改名后，首页收藏条仍显示旧条目；收藏条目无法从首页移除，只能清空全部收藏。

**建议**

- 读取收藏和最近阅读时过滤不存在的文件。
- 首页长按卡片提供“移除收藏/移除记录”。
- 仓库重新克隆后保留元数据时，同时清理已不存在的路径。

## 4. P2：兼容性与一致性问题

### 4.1 Front matter 与标签

- 只支持 `tags: a, b`，不支持 YAML 块状列表：

  ```yaml
  tags:
    - flutter
    - notes
  ```

- 标签扫描 `TagIndex._readTags()` 固定使用 `utf8.decode(allowMalformed: true)`，GBK 中文标签会乱码；阅读页使用 `decodeTextBytes`，两边结果不一致。
- Front matter 解析只支持 `title` / `tags`，不展示 date、description、author、cover 等常见字段。
- 建议实现一个最小 YAML 子集：块状列表、行内数组、引号、简单转义；标签扫描复用同一解码函数。

### 4.2 `.mdx` 的类型不一致

- `NoteScanner.mdExtensions` 不包含 `.mdx`。
- `RepoSearchService`、`TagIndex`、`LinkChecker` 都把 `.mdx` 当 Markdown。
- 打开 `.mdx` 时进入代码查看器，但搜索/标签/断链检查又按 Markdown 处理。

建议二选一：

1. 支持 `.mdx` 渲染（至少按 Markdown 处理）；
2. 明确不支持，改由代码查看器打开，并从 Markdown 搜索/标签/断链扫描中排除。

### 4.3 UTF-16 文本

`decodeTextBytes` 只处理 UTF-8（含 BOM）与 GBK。UTF-16 LE/BE 文件会乱码。建议检测 BOM 并用对应解码器处理，至少给出“不支持 UTF-16”的明确提示。

### 4.4 GFM alert 与代码块

`splitGfmAlerts()` 在 Markdown 解析前按行扫描，不跳过围栏代码块。代码块中形如 `> [!NOTE]` 的行可能被拆成告警块，破坏代码渲染。

建议在分割前复用 TOC 的围栏跟踪逻辑，或先标记代码块区间再处理。

### 4.5 链接与锚点

- 跨文件锚点 `other.md#heading` 只打开文件顶部，不跳到标题。
- 重复标题的 GitHub 风格 `-1` 后缀锚点不支持。
- `mailto:`、`tel:` 等非 http(s) 链接点击后静默无反应。
- 相对路径边界使用 `startsWith(repoRoot)`，`notes2` 会被误判在 `notes` 内；目录链接指向仓库根时还可能触发 `substring` 越界。
- 建议：
  - 用规范化路径 + 路径段边界判断，而不是字符串前缀；
  - 支持跨文件锚点；
  - 对 `mailto:`/`tel:` 调用系统处理器，或至少给出“未处理链接”的提示；
  - 为重复标题生成稳定锚点。

### 4.6 断链检查漏报

`LinkChecker` 只识别行内链接和 HTML 链接，不识别 reference-style 链接与链接定义：

```markdown
[文档][ref]

[ref]: ./missing.md
```

也不检查页内锚点是否存在。建议补充 reference link 解析、锚点校验和进度/取消能力。

### 4.7 Notebook 输出

- stdout/stderr 的 ANSI 转义未清理，tqdm、彩色日志等输出会显示控制字符。
- 不支持的富输出（plotly、HTML widget、application/json 等）在没有 `text/html` 时可能直接消失。
- 建议增加 ANSI 清理；对无法渲染的输出显示“暂不支持该输出类型”的占位。

### 4.8 HTML 笔记兼容

`normalizeHtmlImages` 会直接剥掉 `<a href="...">` 标签，HTML 链接变成普通文字。建议把 HTML 链接转换为 Markdown 链接，而不是只保留内文。

### 4.9 搜索限制与搜索历史

- 全局搜索和仓库内容搜索至少要求 2 个字符，单个汉字无法搜索。
- 内容搜索单文件上限 2 MB，最多返回 60 个命中文件，无分页。
- 搜索历史在每次防抖查询后写入，可能记录 `flut` 这类半截词。
- 没有“清空搜索历史”，只能逐条删除。
- 建议：单字查询允许但限制结果数量；结果分页；历史只在提交/打开结果时写入，并提供清空入口。

### 4.10 同步能力边界

- 克隆不支持分支选择。
- submodule 不会被初始化，目录可能为空。
- Git LFS 文件会显示指针文本，图片无法直接查看。
- 克隆固定 5 分钟超时，大仓库可能失败。
- 建议至少在 UI 中说明这些限制；分支选择和 LFS 指针提示可作为后续增强。

### 4.11 设置页写入与平台适配

- 滑杆 `onChanged` 每次变化都写 `SharedPreferences`，拖动时产生大量磁盘写入。
- 默认用户名逐字写盘。
- 应用图标选择器在 iOS/Windows 仍显示，但实际无效。
- 阅读页音量键始终被拦截，用户无法在阅读时调音量，也没有关闭开关。
- 建议：
  - 滑杆使用本地状态，`onChangeEnd` 再持久化；
  - 文本输入防抖保存；
  - 仅在 Android 显示应用图标设置，或标注“仅 Android”；
  - 为音量键翻页增加开关。

### 4.12 其他小问题

- TOC 标题保留 `**`、反引号等 Markdown 标记，目录里会显示符号。
- 图片缓存淘汰后可能留下孤儿 `.meta` sidecar。
- 仓库页“更多”菜单最后两项缺图标。
- 设置页与仓库页都叫“检查更新”，但一个查应用 Release，一个查 git 远端提交，容易被误解。
- 删除仓库使用普通按钮样式，建议危险操作使用错误色并说明元数据是否保留。

## 5. 功能建议

以下按“对笔记用户的价值 / 实现成本”排序，不包含 README 明确非目标。

### 5.1 阅读体验

1. **局部文字选择与复制**：段落选中、复制引用、选中查词。
2. **阅读主题**：sepia 暖色、OLED 纯黑；设置页直接调正文字号和字体。
3. **TOC 过滤/搜索**：长文档目录可输入关键词筛选。
4. **标签可点击**：阅读页顶部的 tags 点击后直接按该标签筛选，而不是只显示文本。
5. **Front matter 元信息**：展示 date、author、description、cover 等常见字段。
6. **可选本地高亮/批注**：只存应用 meta，不修改仓库文件；作为后续功能，不进入第一版核心范围。

### 5.2 本地笔记工作流

1. **本地文件夹与 git 仓库完全同权**：首页继续阅读、收藏、最近阅读、全局搜索均覆盖本地镜像。
2. **新建/重命名笔记**：当前只能编辑已有文件；支持在镜像目录和 SAF 源文件夹同时创建空笔记。
3. **编辑器增强**：查找替换、Markdown 语法高亮、预览定位。
4. **外部文件变化提示**：本地文件夹重新同步时，如果镜像有未写回修改，首页已有提示；可进一步提供逐文件差异查看。

### 5.3 搜索

1. 全局搜索覆盖本地文件夹。
2. 单字中文可搜索，结果分页。
3. 搜索结果定位到具体命中行，而不是所属章节标题。
4. 支持精确短语、排除词等简单查询语法。

### 5.4 笔记生态兼容

1. 可选支持 Obsidian 风格 `[[note]]`、`![[image]]`。
2. 支持 inline `#tag`，与 front matter tags 合并。
3. 支持 YAML 块状 tags 和常见 front matter 字段。
4. 断链检查支持 reference-style links 和页内锚点。

### 5.5 仓库与同步

1. 首页仓库置顶、排序、分组。
2. 克隆时可选分支。
3. LFS 指针文件给出明确提示，或支持按需下载。
